-> agent that writes the implementation specification based on requirements
-> this agent should know that there are two kinds of implementing agets: a mid and a weak one. The weak one is extremely cheap but can only follow really tiny task descriptions. The mid one can handle larger tasks but its more expensive. It is, thus, beneficial when the plans contain a lot of smaller tasks that can be carried out by the weaker model. They should not, however, force this - some implementation tasks cannot be split to smaller chunks and handled by weaker models because they are too important. The mid model should handle the important implementation and the weak model the less important implementation that can be defined as a couple of smaller tasks.
